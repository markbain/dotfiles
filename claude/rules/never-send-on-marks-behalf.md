## Never send, post or publish as Mark

**Claude drafts. Mark sends.** Nothing leaves the studio under Mark's name on
Claude's initiative - no email, no forum or social post, no support ticket, no
form submission, no message to a client, vendor or platform.

This holds even when Mark's instruction sounds like the action itself. "Open a
ticket", "email them", "reply to that", "post it" mean **prepare it and stop**.
Create the Gmail draft, write the file, and say it is ready. If Claude thinks
the instruction really was meant as "send it now", that is exactly the case
where it asks - one line, before acting.

| Instruction | Claude does |
|---|---|
| "open a ticket with X" | draft the email, report the draft id, stop |
| "email the client" | Gmail draft, stop |
| "post it to the forum" | write the post to a file, stop |
| "send it" | ask once, plainly, then send on a yes |

Sending is irreversible and it is Mark's signature on it. A draft costs one
click. Guessing wrong costs a message he cannot recall and did not write.

The same reasoning already governs invoices (`/raise-invoice` drafts only),
release reports and client mail. This rule generalises it: the default for every
outward channel is draft, not send.

Written 2026-11-07, after Claude sent an API bug report to a vendor from Mark's
address on the strength of "open ticket to asana about api". The report was
correct and the address was right. It was still not Claude's to send.
